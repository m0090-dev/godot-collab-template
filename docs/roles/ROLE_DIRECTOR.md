# 役割メモ: 演出担当

シナリオと演出が担当範囲。開始時に `docs/FOR_PARTNER.md` も読むこと。

## 作業の進め方

1. やりたい場面を自然言語で AI に伝える（セリフ、動き、雰囲気）。
2. AI が Godot のシーンとスクリプトに実装し、読み込みチェックと Web 書き出しで「壊れていない」ことを確認する。
3. AI は確認用の自動再生動画を作って報告に添える。
4. 演出担当はスマホで動画と Pages のテスト公開を見て、直したい所を言葉で伝える。
5. まとまったら管理担当に報告する。

## 演出の道具（Godot でできることの目安）

- 基本: Tween や AnimationPlayer による移動・拡大・回転・揺れ、カメラ演出
  （Camera2D / Camera3D の寄り・引き・手ぶれ）、視差スクロール、残像、
  パーティクル（雨・雪・火花・煙など）。
- 応用: シェーダ（グリッチ、色ずれ、ゆらぎ、輪郭強調など。2D / 3D 両方）、
  物理演算（物が落ちる・跳ねる・積み上がる）、2D と 3D の混在、
  音に合わせた演出。
- 特殊: スクリプトによるカスタム演出（入力に反応する仕掛け、ミニゲーム等）、
  メタ演出（セーブを跨ぐ記憶、作中の偽 UI やエラー画面、実時刻連動など）。
  ただし Web 版では実ファイルや OS には触れないので、メタ演出は「作中の仮想環境」として再現する形になる。

## 提案の出し方（触れるモックで提案する）

演出の方向を決めるときは、文章だけでなく、可能な場合は HTML/CSS/JS の
簡単なモックをその場で作って見せる。偽の場面（背景、ダミーの立ち絵、セリフ枠）に
効果を付け替えられる形にし、ボタンで切り替え、スライダで強さを変え、
「再生」でタイミングを再現する。返答は選択肢（タップで選べる形）＋自由入力の
両方を受け付ける。

例: 演出担当が「雨の場面で、決め台詞の直前に一瞬だけ画面を歪ませて、
そのあと静かに戻したい」と言ったとき、AI はこう返す。

- モック: 雨っぽい背景＋ダミー立ち絵＋セリフ枠。効果ボタン
  （なし / ゆがみ / グリッチ / ズーム）、強さスライダ、再生ボタンを付ける。
- 選択肢: 「歪ませて戻す（元の案）」「グリッチで一瞬だけ」「ズームで寄る」の 3 案と、
  自由入力欄（「もっと弱く」「音も入れたい」等）。
- モックは方向と数値を決めるための仮再現であり、本物は Godot に実装して
  テスト公開と動画で確認する、と添える。

## AI の機能差への対応（どの AI でも回る形にする）

使う AI によってできることが違う。前提にしていいのは「文章で考え、文章で返す」
ところまでで、それ以外はあれば使う任意の上乗せとして扱う。

- 核（どの AI でも）: 場面の相談、選択肢の提示（文章）、シーンとスクリプトの作成と説明、
  報告文の作成。これだけで作業が完結するようにする。
- 上乗せ（できれば使う）: 触れるモック（HTML/CSS/JS）の提示、選択肢 UI、
  スクリーンショット。できない環境では文章の選択肢と説明に置き換える。
- 上乗せ（エージェント系の AI のみ）: 書き出しと読み込みチェックの実行、自動再生動画の作成、
  ブラウザでの実表示確認。動画や実行確認は、Muse のようなエージェント機能を持つ
  AI でしかできない前提で、できない場合は「人間がテスト公開で確認する」に切り替える。
- 機能があっても制限がすぐ来て実用にならない場合は、使えないものとして扱い、
  下の段にフォールバックする。
- 指示文は特定の AI の機能名に依存して書かない。「○○機能で作れ」ではなく
  「可能ならモックで、無理なら文章で」と、手段と代替をセットで書く。

## 素材について

- 演出はダミー素材（本番と同名・同寸法）で組む。本番素材が来てもコードは変えなくてよい。
- 欲しい素材が増えたら `assets_manifest.txt` に行を足す（それが管理担当側の TODO になる）。
- まとまった依頼は Issue でも出す（`.github/ISSUE_TEMPLATE/resource-request.md`。宛先は主にリソース担当）。連携の前提は `docs/START_HERE.md` の「GitHub 連携の前提」を参照。
